Why this needs its own plan

AI is already part of how work gets done at Forge & Spark. It is not, however, part of any shared system. Right now, use is real but informal: Claude chat and Cowork are the default, but that splits further the moment someone hits a credit limit or needs something those tools do not do well, and there is no picture yet of where people land after that or why.

What is already working

Some of this is solid and worth keeping as-is, though parts of it are assumptions rather than confirmed fact, flagged below as exactly that.

  • Cowork, Claude chat, Perplexity, and ChatGPT are already in active use across the team (need to confirm this is the full and accurate picture)
  • Claude chat is also where files get uploaded into Projects (need to confirm that work actually lands in Drive or locally, not just inside Claude's own project space)
  • Lara is currently the only one working directly in code rather than chat (need to confirm this is still true), which avoids the rewrite-copy-paste cycle of chat-based editing and holds up better over a long working session
  • A personal naming convention for folders already exists for Lara's own work and holds up well day to day

Where it breaks down

Past that starting point, there is no shared system. That gap is sharper because the team is fully remote and mostly part-time, so people move in and out of projects without always holding the full picture, and there is no system today for posting or checking updates on what is happening. Project managers may hold some of that picture, but from a PM perspective, not a creative one. What's missing is a way to align the team from the creative side, one place to see updates, rather than several documents and project tools that each have to be checked separately.

  • No system for posting or checking updates, so picking a project back up means reconstructing where it left off from scratch
  • No visibility into what people do when Claude runs out of credits, or which other platform they move to and why
  • No shared naming or folder convention past the one that already exists individually
  • No consistent way to track which parts of a client engagement involved AI-assisted work
  • No agreed pattern for when a task calls for chat, for Cowork, or for working directly in code

Cowork projects versus Claude chat Projects: these are not the same thing, even though they share a name, and mixing them up has real consequences for where a file actually ends up. Cowork projects cannot write files directly, work has to be copied back out and brought into Drive by hand. Claude chat Projects is a knowledge space for a conversation: files uploaded there give Claude context to work from, but they do not automatically end up saved anywhere outside Claude. Both are already in active use, so it is worth confirming, project by project, where the real, durable copy of the work actually lives.

None of that is a crisis. It is the normal state of a tool that got adopted faster than a system could be built around it.

Why this is worth doing properly

Efficiency: the point of this work is to make the studio meaningfully more efficient, not to add process for its own sake. A shared system only earns its place if it removes friction people can feel.

Consistency: a shared naming and folder convention, and a shared sense of which tool fits which task, means work is easier to hand off, easier to pick back up, and easier for anyone (including AI tools themselves) to understand later.

New ways to present work: once the internal workflow is solid, there is real opportunity in how work gets presented to clients, live pages and interactive deliverables rather than static files, building on the direction already started with the Website Updates apps work.

Client insight: understanding how the studio actually works with AI is also a preview of how clients are working, or trying to work. People are already starting to ask about this. Running discovery internally first means any recommendation made to a client is based on something actually tested, not guessed at. Whether that becomes an offered service is not decided, but the discovery work builds the knowledge either way.

Lower risk: switching how people work is a real disruption, not a small one. Getting the order of operations right, understanding first, changing second, is what keeps that disruption worth it instead of just disruptive.

The approach

This is not a rollout plan for new tools. It is a plan for how the studio works, what matters most in that work, and how it gets documented, so that any tool decisions serve that instead of leading it. The phases below are deliberately sequential: nothing in Phase 2 gets decided until Phase 1 has real answers, because right now, honestly, some of those answers are not known yet.

This also needs to connect back to the AI guidelines that already exist in the project system. They are already written and accurate, but almost no one reads them in practice. Part of what this plan needs to solve is making that guidance something people actually encounter and use, not a document that exists somewhere and gets forgotten. (Link to add here once located.)

Underneath all of it is the same goal: get the studio's own AI workflow solid enough that any recommendation made to a client is standing on something real, not a guess. That is the order of operations, our workflow first, client recommendations second, not the other way around.

Worth naming directly: changing how a team works, and changing shared structure, are both significant even when the change is good. This plan treats that as a real cost to manage, not a footnote.

Phase 1: Discovery  ↻ Next
Find out how the studio actually uses AI today, before deciding anything about what should change.
1

Which tool, for which kind of work

For each person: what gets done in Claude chat or Projects, what gets done in Cowork, Perplexity, or ChatGPT, and what (if anything) already happens in code.

2

What happens at the credit limit

When Claude runs out of credits mid-task, which platform does each person move to, and why that one specifically.

3

How work gets named, saved, and handed off

Whether each person has their own system, a shared one, or none, and what happens when work needs to be picked up by someone else.

4

Where AI already touches client work

Any place AI is already part of a client deliverable today, even informally or without anyone deciding it should be.

5

What is frustrating or slow right now

In the team's own words, not assumed. This is the question most likely to surface something Phase 2 needs to solve for.

6

What people already know is possible

A baseline for how much of this is a tooling gap versus an awareness gap, since the two need different fixes.
