# Oliver Content Board

The client-facing board showing every Oliver blog, what's inside each package, and who owes what.

**Live:** https://larahkroeker.github.io/fs-apps/clients/OLIVER-content-board.html
(`noindex` — it won't show up in search, but anyone with the link can read it.)

Built for Forge & Spark's Oliver engagement. One self-contained HTML file, ~0.7 MB, no external
requests except the Manrope webfont. Email it, drop it in Drive, open it offline — it works.

---

## Refresh and publish

```bash
cd ~/Sites/fs-apps/_src/oliver-board
python3 build.py          # writes ../../clients/OLIVER-content-board.html
cd ~/Sites/fs-apps
git add -A && git commit -m "Update Oliver board" && git push
```

GitHub Pages picks it up in roughly 20–60 seconds.

`build.py` writes **straight to the published location**, so there is no copy step and no second
copy to drift out of date.

## When the content calendar changes

`build.py` reads `sheet.json` — a **snapshot** of the Google Sheet, not the live sheet. Re-running
the build alone will not pull new data. To refresh it:

1. Export the calendar as `.xlsx` and save it here as `calendar.xlsx`.
   Source: [Oliver | Deliverables Tracker & Content Calendar](https://docs.google.com/spreadsheets/d/1Wm_pWJqyg4NRmZVk875g7TcV4PKTE8v7WpFoseOMNxA/edit)
2. `python3 parse.py` — rewrites `sheet.json` and re-extracts the pasted post creatives into `media/`.
3. `python3 build.py`, then commit and push.

`parse.py` reads every monthly tab plus the Deliverables tab, and pulls the images people paste
into the **Asset Preview** column (they come out of the .xlsx as embedded files, matched back to
their row via the drawing anchors).

## What lives where

| File | What it holds |
| --- | --- |
| `build.py` | All the content, statuses, owners and copy decisions. **Edit this to change what the board says.** |
| `template.html` | Page shell, CSS, filter JavaScript. **Edit this to change how it looks.** |
| `parse.py` | Google Sheet `.xlsx` → `sheet.json` + `media/` |
| `featured_image.py` | Pulls a blog's featured image out of a package doc (see below) |
| `sheet.json` | Calendar snapshot the build reads. Regenerate with `parse.py`. Not in git. |
| `calendar.xlsx` | The raw export. Not in git. |
| `media/` | Post creatives pasted into the spreadsheet. Regenerated by `parse.py`. Not in git. |
| `featured/` | Blog featured images (see below) |
| `hero_poster.jpg` | The blue graphic behind the header — Oliver's own hero video still |
| `logo.svg` | Oliver logo, recoloured for a dark background |
| `thumbs/` | Generated JPEG cache. Safe to delete; rebuilds itself. Not in git. |

## Editing the board

Almost everything is a Python literal near the top of `build.py`:

- **`BLOGS`** — one dict per blog: title, status, live URL and date, package doc, story pillar,
  audience, CTA, featured image, and its `todo` list of `(what, who)` pairs.
- **`SPECIALS`** — the special projects. Each has `what` (plain description), `why` (why it
  matters, tied back to the roadmap), an optional `note` + `note_label` callout, `todo`, `links`.
- **`REPORTS`** — the monthly reports.
- **`OVERRIDE`** — real-world truth the tracker hasn't caught up with. Statuses here **win over
  the spreadsheet**. The Sales Deck lives here because the tracker still says "Scheduled" when it's
  actually waiting on final design.
- **`CHAIN`** / **`OBJECTIVES`** — the "Why we publish" panel, taken from the Content Roadmap
  (OKRs updated July 2026).
- **`REF_LINKS`** — the buttons in the header.

Blog statuses and live URLs were verified against oliver.app/blog directly, not taken from the
tracker — the tracker dates all three live blogs 6 Apr, the site says 14 and 16 Apr.

## Featured images

Two sources, in order of authority:

1. **Published blogs** — the real hero image from the live post on oliver.app.
2. **Unpublished blogs** — the photo directly under the H1 in the package doc.

To pull one from a package doc, download the doc as `.docx`, then:

```bash
python3 featured_image.py <base64-json-file> featured/<name> "IMAGE GUIDANCE"
```

The last argument is text to anchor on; the script takes the first image *after* it. Then point the
blog's `featured=` key at the result.

"How Advisors Close Deals Faster" has no featured image because that package doc contains no
images at all (17 KB). Its card shows "No creative yet" honestly rather than a placeholder.

Portrait creatives are detected by aspect ratio and shown whole (`background-size: contain`)
instead of being cropped to the landscape card.

## Known data problems

Found while building this, all still true as of 17 Aug 2026 and worth fixing at source:

- The **FEEL / BELIEVE / KNOW framework** pasted into the package docs describes *Forge & Spark's*
  pillars — "Show how Forge & Spark can help", "purpose-led brands". It's template boilerplate
  sitting in client-facing documents. Present in at least the Award, Advisors and Modernization docs.
- The **Award blog's story pillar disagrees** with itself: the package doc says Connected Systems,
  the Content Roadmap's Go-Ahead Blogs table says Better Human Experience. The board follows the
  roadmap.
- The **Advisors package** has empty social copy and two Canva links pointing at September's
  Healthy Habits graphics.
- The **Award package** has a Post 3 Canva link whose label and destination are different files.
- The Award doc's newsletter teaser asks for a teaser for "the monthly **F&S** newsletter".
- **Healthy Habits** doesn't map to any of the three story pillars and targets plan members, while
  every roadmap persona is a B2B buyer. It's also marked Approved while the two on-strategy B2B
  blogs wait.
- The roadmap describes the website as **Duda**; the live site and the form recommendations doc
  are both **Webflow**.

## Notes

- `sheet.json`, `calendar.xlsx`, `media/` and `thumbs/` are gitignored. This repo is served
  publicly by GitHub Pages, so the raw calendar data stays local rather than sitting at a
  fetchable URL. A fresh clone will need step 1–2 above before it can build.
- Dates: `TODAY` in `build.py` is hardcoded so "days past post date" stays reproducible. Update it
  when you refresh.
- Requires macOS `sips` for image resizing (built in). No pip installs, stdlib only.
